# Contracts

> **For Claude:** the code in this document is **normative**. Each section corresponds to
> one file in `packages/contracts/src/`; copy it verbatim. It was typechecked with
> Zod 4 and TypeScript strict mode (CONV-001) before being written here. Do not add,
> rename, or reshape fields in code; change this document first (OVR-020).

This document defines the data shapes shared across modules and with the client:
primitives, rules values, rulings, entities, world state, turns, memory, commits,
jobs, errors, and events. It does **not** define content-pack file formats
(`04-content-schemas.md`), provider interfaces (`05-providers.md`), extraction output
(`08-memory.md`), or HTTP request/response bodies (each feature's doc).

## 1. Principles

- **CON-001** Zod schemas are the single source of truth. TypeScript types are always
  `z.infer` of a schema (CONV-006).
- **CON-002** `packages/contracts` contains schemas, inferred types, and the `Result`
  helper only. No game logic.
- **CON-003** **Model-facing schemas never require the model to produce a UUID.**
  Models reference entities by `EntityId` and clocks by `ClockId`; the engine assigns
  all UUIDs. Model-facing schemas in this document: `Ruling` and everything it contains.
- **CON-004** Model-facing schemas MUST be convertible with `z.toJSONSchema` for
  constrained decoding: no `.refine`, `.transform`, `.preprocess`, or custom types.
  Cross-field rules that cannot be expressed structurally are **invariants**, enforced
  by semantic validation in `core` and listed under each section below.
- **CON-005** Invariants apply to all data, not only model output. Semantic validation
  runs before any commit set is applied; a violation rejects the whole set with
  `illegal_state_change`.

## 3. Primitives — `primitives.ts`

```ts
import { z } from 'zod';

/** Runtime-generated record ID (turns, commits, observations, statuses, …). */
export const IdSchema = z.uuid();
export type Id = z.infer<typeof IdSchema>;

/** Entity kinds. The prefix of every EntityId. */
export const EntityKindSchema = z.enum(['pc', 'npc', 'place', 'faction', 'item']);
export type EntityKind = z.infer<typeof EntityKindSchema>;

/**
 * Human-readable entity ID: `<kind>.<slug>`, e.g. `npc.varek`, `place.old-mill`.
 * Content-authored entities use authored slugs; runtime-created entities get a
 * slug plus a 4-char suffix, e.g. `npc.bartender-7f3a`. Models read and write these.
 */
export const EntityIdSchema = z
  .string()
  .regex(/^(pc|npc|place|faction|item)\.[a-z0-9]+(?:-[a-z0-9]+)*$/);
export type EntityId = z.infer<typeof EntityIdSchema>;

/** Integer minutes since the campaign epoch. The only internal time value. */
export const GameTimeSchema = z.int().nonnegative();
export type GameTime = z.infer<typeof GameTimeSchema>;

/** Real-world timestamp, ISO 8601 UTC. Used only for records, never for game logic. */
export const WallTimeSchema = z.iso.datetime();
export type WallTime = z.infer<typeof WallTimeSchema>;

/**
 * Where the server reads wall time: `now()` is milliseconds since the Unix epoch. Injected
 * so tests can fix it (CONV-061). Not "clock": a clock is the progress tracker.
 */
export type TimeSource = { now(): number };

export const SchemaVersionSchema = z.int().positive();
```

- **CON-010** Entity IDs never change after creation. Renaming changes `name`, not `id`.
- **CON-011** Runtime-created entity IDs are `<kind>.<slug-of-name>-<4 lowercase hex>`,
  generated by the engine, unique within the campaign, and never reused, including
  after an entity dies or is removed. Copies made by copy-on-write keep their entity
  IDs: the same entity in two timelines (TRN-115).
- **CON-012** `GameTime` is the only time value used by game logic. `WallTime` is for
  records and display.

## 4. Rules values — `rules.ts`

```ts
import { z } from 'zod';
import { EntityIdSchema, GameTimeSchema, IdSchema } from './primitives';

/*
 * Rules values are defined by the campaign's ruleset (07-rules). The ranges below are
 * outer limits only; the ruleset narrows them, and semantic validation enforces it.
 */

/** A stat ID from the ruleset, e.g. "str". */
export const StatIdSchema = z.string().regex(/^[a-z][a-z0-9]{0,11}$/);
export type StatId = z.infer<typeof StatIdSchema>;

export const StatRatingSchema = z.int().min(-5).max(20);

/** Keys are exactly the ruleset's stat IDs (CON-024). */
export const StatBlockSchema = z.record(StatIdSchema, StatRatingSchema);
export type StatBlock = z.infer<typeof StatBlockSchema>;

/** GM-set adjustment from the situation, in points (RUL §3.2). */
export const DifficultySchema = z.int().min(-10).max(10);

export const RollResultSchema = z.enum(['critical', 'success', 'partial', 'failure']);
export type RollResult = z.infer<typeof RollResultSchema>;

export const EffectLevelSchema = z.enum(['limited', 'standard', 'great']);
export type EffectLevel = z.infer<typeof EffectLevelSchema>;

export const DieValueSchema = z.int().min(1).max(100);

/** One labeled adjustment to a dice pool or to effect, shown on the dice card (RUL §3). */
export const RollModifierSchema = z.object({
  source: z.enum(['item', 'harm', 'ruling', 'critical']),
  label: z.string().min(1).max(80), // e.g. "Grappling hook", "Cracked Ribs (moderate)"
  value: z.int().min(-20).max(20), // points (RUL §3.2)
});
export type RollModifier = z.infer<typeof RollModifierSchema>;

/** A completed roll. Raw dice are always recorded (CONV-062). Reading rules: RUL §3. */
export const RollSchema = z.object({
  stat: StatIdSchema,
  rating: StatRatingSchema,
  difficulty: DifficultySchema,
  modifiers: z.array(RollModifierSchema), // item and harm points
  points: z.int(), // rating + difficulty + sum(modifiers)
  method: z.enum(['pool-highest', 'pool-count', 'sum']),
  sides: z.int().min(2).max(100),
  dice: z.array(DieValueSchema).min(1),
  kept: z.array(DieValueSchema).min(1), // all dice, or the kept die for an empty pool
  total: z.int(), // the value read: highest die, successes counted, or sum plus bonus
  result: RollResultSchema,
  effectModifiers: z.array(RollModifierSchema), // ruling, harm, critical
  effect: EffectLevelSchema.nullable(), // null for resistance rolls
});
export type Roll = z.infer<typeof RollSchema>;

/** 1 = least severe. The ruleset defines the levels; one above its last is fatal. */
export const HarmLevelSchema = z.int().min(1).max(9);
export type HarmLevel = z.infer<typeof HarmLevelSchema>;

/** A harm tag ID from the ruleset, e.g. "physical". */
export const StatusTagSchema = z.string().regex(/^[a-z][a-z0-9-]{0,23}$/);

/** Any named condition on a character. Harm is a status with a level. */
export const StatusSchema = z.object({
  id: IdSchema,
  name: z.string().min(1).max(80), // e.g. "Deep Cut to Arm"
  kind: z.enum(['harm', 'condition']),
  level: HarmLevelSchema.optional(), // required when kind is 'harm'
  tags: z.array(StatusTagSchema),
  note: z.string().max(500).optional(),
  permanent: z.boolean(), // never heals (RUL §6.5)
  treated: z.boolean(), // harm only: heals at the treated rate
  inflictedAt: GameTimeSchema,
  changedAt: GameTimeSchema, // when the level last changed; starts the healing timer
});
export type Status = z.infer<typeof StatusSchema>;

export const ConsequenceTypeSchema = z.enum([
  'reduced-effect',
  'complication',
  'lost-opportunity',
  'worse-position',
  'harm',
]);
export type ConsequenceType = z.infer<typeof ConsequenceTypeSchema>;

/** What a planned consequence can be: a cost (above), or something the actor achieves. */
export const PlannedConsequenceTypeSchema = z.enum([
  'progress', // the actor achieves something; may tick a clock
  'treatment', // the actor treats a character's harm
  'reduced-effect',
  'complication',
  'lost-opportunity',
  'worse-position',
  'harm',
]);
export type PlannedConsequenceType = z.infer<typeof PlannedConsequenceTypeSchema>;

export const ClockIdSchema = z.string().regex(/^clock\.[a-z0-9]+(?:-[a-z0-9]+)*$/);

export const ClockSchema = z.object({
  id: ClockIdSchema, // e.g. clock.guard-alert
  name: z.string().min(1).max(80),
  segments: z.int().min(2).max(24),
  filled: z.int().nonnegative(),
  visibility: z.enum(['player', 'gm']),
  ownerId: EntityIdSchema.optional(),
  kind: z.enum(['progress', 'stat-change']),
  statChange: z
    .object({
      characterId: EntityIdSchema,
      stat: StatIdSchema,
      delta: z.int().min(-3).max(3), // non-zero
    })
    .optional(), // required when kind is 'stat-change'
});
export type Clock = z.infer<typeof ClockSchema>;
```

**Invariants**

- **CON-020** A status with `kind: 'harm'` has a `level`; a status with
  `kind: 'condition'` has no `level` and `treated: false`.
- **CON-021** A clock's `filled` is between 0 and `segments` inclusive.
- **CON-022** A clock with `kind: 'stat-change'` has `statChange`; other clocks do not.
- **CON-023** A roll's `points` equals `rating + difficulty + sum(modifiers)`; its
  `dice`, `kept`, `total`, and `result` follow the ruleset's dice method
  (`07-rules.md` §3.3); and `effect` is null exactly when it is a resistance roll.
  Rolls are produced by `core`, never by a model.
- **CON-024** Rules values are bounded by the campaign's ruleset, not by these schemas,
  which only set outer limits. Semantic validation checks that: a stat block's keys are
  exactly the ruleset's stat IDs and its ratings are within `stats.min…max`; every stat
  ID anywhere (rolls, item bonuses, stat-change clocks) and every status tag is defined
  by the ruleset; harm levels do not exceed the fatal level (`harm.levels.length + 1`);
  clock segments and ticks are within `clocks`; and relationship values are within
  `relationships.min…max`.

## 5. Rulings — `ruling.ts`

The output of the adjudication step. Model-facing (CON-003, CON-004).

```ts
import { z } from 'zod';
import { EntityIdSchema } from './primitives';
import {
  ClockIdSchema,
  DifficultySchema,
  EffectLevelSchema,
  HarmLevelSchema,
  PlannedConsequenceTypeSchema,
  StatIdSchema,
  StatusTagSchema,
} from './rules';

/**
 * Limits that narrow the model-facing ruling schema to one campaign's ruleset (CON-035).
 * `core` derives them from the ruleset; `BROAD_RULING_LIMITS` gives the storage schema.
 */
export type RulingLimits = {
  statIds: readonly [string, ...string[]] | null; // null = any stat ID
  tagIds: readonly [string, ...string[]] | null; // null = any tag ID
  difficulty: { min: number; max: number };
  maxHarmLevel: number; // the ruleset's fatal level
  clockSegments: { min: number; max: number };
  maxTicks: number;
};

export const BROAD_RULING_LIMITS: RulingLimits = {
  statIds: null,
  tagIds: null,
  difficulty: { min: -10, max: 10 },
  maxHarmLevel: 9,
  clockSegments: { min: 2, max: 24 },
  maxTicks: 6,
};

/** Builds every model-facing ruling schema for the given limits. */
export function makeRulingSchemas(limits: RulingLimits) {
  const stat: z.ZodType<string> = limits.statIds ? z.enum(limits.statIds) : StatIdSchema;
  const tag: z.ZodType<string> = limits.tagIds ? z.enum(limits.tagIds) : StatusTagSchema;
  const harmLevel = HarmLevelSchema.max(limits.maxHarmLevel);
  const difficulty = DifficultySchema.min(limits.difficulty.min).max(limits.difficulty.max);

  /**
   * Something the GM intends to happen as part of an outcome. No UUIDs (CON-003).
   * - `harm` is required when type is 'harm'.
   * - `clockTicks` is allowed on 'progress' and 'complication'.
   * - `treatment` is required when type is 'treatment'.
   * Values are written for standard effect; roll rulings scale success items (RUL §4.3).
   */
  const plannedConsequence = z.object({
    type: PlannedConsequenceTypeSchema,
    targetId: EntityIdSchema,
    description: z.string().min(1).max(300),
    harm: z
      .object({
        level: harmLevel,
        name: z.string().min(1).max(80),
        tags: z.array(tag).min(1),
      })
      .optional(),
    clockTicks: z
      .object({ clockId: ClockIdSchema, ticks: z.int().min(1).max(limits.maxTicks) })
      .optional(),
    treatment: z
      .object({ harmName: z.string().min(1).max(80).nullable() }) // null = the most severe harm
      .optional(),
  });

  /** A clock the GM introduces in this ruling. Created before any ticks apply. */
  const plannedClock = z.object({
    id: ClockIdSchema,
    name: z.string().min(1).max(80),
    segments: z.int().min(limits.clockSegments.min).max(limits.clockSegments.max),
    visibility: z.enum(['player', 'gm']),
    ownerId: EntityIdSchema.optional(),
    kind: z.enum(['progress', 'stat-change']),
    statChange: z
      .object({ characterId: EntityIdSchema, stat, delta: z.int().min(-3).max(3) })
      .optional(),
  });

  /** Explanations for a ruling, one per explanation level above 'off'. */
  const explanation = z.object({
    playerSafe: z.string().max(600), // uses only what the PC knows
    full: z.string().max(1200), // may include hidden truth
  });

  /** The GM decided the outcome from the fiction; no roll. Values are applied as written. */
  const direct = z.object({
    kind: z.literal('direct'),
    elapsedMinutes: z.int().nonnegative(), // game time the action takes
    outcome: z.enum(['success', 'partial', 'failure']),
    effect: EffectLevelSchema,
    clocks: z.array(plannedClock).max(3),
    consequences: z.array(plannedConsequence),
    explanation,
  });

  /**
   * Stakes, set before the roll (RUL §4.2):
   * - `success`: what the actor achieves. Applied on critical, success, and partial.
   * - `partial`: costs added on a partial.
   * - `failure`: costs on a failure. Success items do not apply.
   */
  const stakes = z.object({
    success: z.array(plannedConsequence).min(1),
    partial: z.array(plannedConsequence).min(1),
    failure: z.array(plannedConsequence).min(1),
  });

  /** The GM calls for a roll. */
  const roll = z.object({
    kind: z.literal('roll'),
    elapsedMinutes: z.int().nonnegative(),
    actorId: EntityIdSchema,
    stat,
    difficulty, // the situation only; the engine applies harm and items
    effectModifier: z.int().min(-1).max(1), // tools, scale, quality of the approach
    itemIds: z.array(EntityIdSchema).max(3), // items the actor uses for a roll bonus
    intent: z.string().min(1).max(300), // what the actor is trying to achieve
    clocks: z.array(plannedClock).max(3),
    stakes,
    explanation,
  });

  /** Out-of-character input: the GM answers the player directly. */
  const ooc = z.object({
    kind: z.literal('ooc'),
    reply: z.string().min(1).max(2000),
    elapsedMinutes: z.int().nonnegative(), // > 0 for skips, e.g. "skip to morning"
  });

  /** Output of the adjudication step. Model-facing. */
  const ruling = z.discriminatedUnion('kind', [direct, roll, ooc]);

  return { plannedConsequence, plannedClock, explanation, direct, stakes, roll, ooc, ruling };
}

const broad = makeRulingSchemas(BROAD_RULING_LIMITS);

/** Storage and API schemas: any ruleset's values pass; semantic validation narrows them. */
export const PlannedConsequenceSchema = broad.plannedConsequence;
export type PlannedConsequence = z.infer<typeof PlannedConsequenceSchema>;
export const PlannedClockSchema = broad.plannedClock;
export type PlannedClock = z.infer<typeof PlannedClockSchema>;
export const RulingExplanationSchema = broad.explanation;
export const DirectRulingSchema = broad.direct;
export const RollStakesSchema = broad.stakes;
export const RollRulingSchema = broad.roll;
export const OocRulingSchema = broad.ooc;
export const RulingSchema = broad.ruling;
export type Ruling = z.infer<typeof RulingSchema>;
```

**Invariants**

- **CON-030** A planned consequence has `harm` exactly when `type` is `harm`, and
  `treatment` exactly when `type` is `treatment`.
- **CON-031** `clockTicks` appears only on `progress` and `complication`, and references
  an existing clock or one planned in the same ruling.
- **CON-032** Every `targetId` and `actorId` references an existing, living character
  present in the scene, unless the ruleset allows off-scene targets.
- **CON-033** `explanation.playerSafe` MUST NOT reveal information the PC does not
  know. This cannot be validated mechanically; it is enforced by prompt design and
  reviewable in the context inspector.
- **CON-034** A roll ruling's `itemIds` reference items the actor possesses (RUL-023),
  and its planned clocks have IDs not already in use (RUL-064).
- **CON-035** The schemas exported here accept any ruleset's values and are used for
  storage and the API. The schema sent to a model is built per campaign with
  `makeRulingSchemas(rulingLimitsFor(ruleset))`, so constrained decoding is limited to
  the ruleset's stat IDs, tag IDs, and ranges (RUL-065).

## 6. Entities — `entities.ts`

```ts
import { z } from 'zod';
import { EntityIdSchema } from './primitives';
import { StatBlockSchema, StatIdSchema, StatusSchema, StatusTagSchema } from './rules';

/** Reserved for phase 9 (ARCH-132). Validated, otherwise ignored until then. */
/**
 * Identity hooks for consistent images (MED §3). Portable: no machine-specific IDs.
 * Generated portraits are campaign assets, not entity fields (MED-010).
 */
export const EntityMediaSchema = z.object({
  referenceImage: z.string().min(1).max(200).optional(), // pack-relative path, e.g. "media/npc.varek.png"
  loraName: z.string().min(1).max(200).optional(), // passed to workflows that map a LoRA input
  loraStrength: z.number().min(0).max(2).optional(),
  imagePrompt: z.string().max(300).optional(), // always-included visual details, e.g. "pale scar through one eyebrow"
});

/**
 * How a character sounds (MED §5). Portable: a description, never a provider's voice ID.
 * Each machine maps characters to its own voices (MED-052).
 */
export const VoiceProfileSchema = z.object({
  description: z.string().min(1).max(200), // e.g. "low, dry, unhurried; a harbor clerk's careful diction"
  speed: z.number().min(0.5).max(2).optional(),
});

const EntityBaseSchema = z.object({
  id: EntityIdSchema,
  name: z.string().min(1).max(120),
  aliases: z.array(z.string().max(120)),
  tags: z.array(z.string().max(40)),
  media: EntityMediaSchema.optional(),
});

/** Required on every character; enforced by the hard floor (13-content-settings). */
export const AgeCategorySchema = z.enum(['adult', 'minor']);

export const CharacterSchema = EntityBaseSchema.extend({
  kind: z.enum(['pc', 'npc']),
  ageCategory: AgeCategorySchema,
  age: z.int().nonnegative().optional(),
  stats: StatBlockSchema,
  statuses: z.array(StatusSchema),
  physicalDescription: z.string().max(1000), // excludes clothing; see appearance
  personality: z.string().max(600), // short, always in context when present (SCH-080)
  goals: z.array(z.string().min(1).max(200)).max(8), // non-empty = active NPC (SCH-081)
  keyNpc: z.boolean(), // always voiced by a separate call (CTX §6)
  locationId: EntityIdSchema.nullable(), // a place, or null if off-map
  lifeState: z.enum(['alive', 'dead']),
  voiceProfile: VoiceProfileSchema.optional(),
});
export type Character = z.infer<typeof CharacterSchema>;

export const PlaceSchema = EntityBaseSchema.extend({
  kind: z.literal('place'),
  parentPlaceId: EntityIdSchema.nullable(),
  description: z.string().max(2000),
});
export type Place = z.infer<typeof PlaceSchema>;

export const FactionSchema = EntityBaseSchema.extend({
  kind: z.literal('faction'),
  description: z.string().max(2000),
  goals: z.array(z.string().min(1).max(200)).max(8), // non-empty = active in world ticks (TIME-060)
});
export type Faction = z.infer<typeof FactionSchema>;

/** Where an item is. Exactly one location at a time. Detailed in 11-gear. */
export const ItemLocationSchema = z.discriminatedUnion('type', [
  z.object({
    type: z.literal('worn'),
    characterId: EntityIdSchema,
    slot: z.string().min(1), // slot name from the slot schema
    layer: z.int().nonnegative(), // 0 = outermost
  }),
  z.object({ type: z.literal('held'), characterId: EntityIdSchema }),
  z.object({ type: z.literal('carried'), characterId: EntityIdSchema }), // encumbrance mode
  z.object({ type: z.literal('contained'), containerId: EntityIdSchema }),
  z.object({ type: z.literal('placed'), placeId: EntityIdSchema }),
  z.object({ type: z.literal('gone') }), // consumed or destroyed
]);
export type ItemLocation = z.infer<typeof ItemLocationSchema>;

export const ItemSizeSchema = z.enum(['tiny', 'small', 'medium', 'large', 'huge']);
export type ItemSize = z.infer<typeof ItemSizeSchema>;

/** An item that holds others: total space in size points, and the largest item that fits (GEAR §5). */
export const ContainerSchema = z.object({
  capacity: z.int().min(1).max(1000),
  maxItemSize: ItemSizeSchema,
});

export const ItemBonusSchema = z.discriminatedUnion('type', [
  z.object({
    type: z.literal('roll'),
    stat: StatIdSchema.optional(), // omitted = any stat when the situation applies
    situation: z.string().min(1).max(200), // e.g. "climbing"
    points: z.int().min(1).max(4), // dice in pool methods; pointValue each in sum (RUL-023)
  }),
  z.object({
    type: z.literal('harm-reduction'),
    levels: z.int().min(1).max(3),
    tags: z.array(StatusTagSchema).min(1),
    usesPerScene: z.int().positive().optional(),
  }),
  z.object({
    type: z.literal('resistance'), // added to resistance rolls against these tags (RUL-087)
    tags: z.array(StatusTagSchema).min(1),
    points: z.int().min(1).max(4),
  }),
]);

export const ItemSchema = EntityBaseSchema.extend({
  kind: z.literal('item'),
  description: z.string().max(1000),
  location: ItemLocationSchema,
  ownerId: EntityIdSchema.nullable(), // who it belongs to, which may differ from who has it
  quantity: z.int().min(1).max(9999), // a stack of identical items, e.g. 15 potions
  weight: z.number().nonnegative().optional(), // per unit; encumbrance mode
  size: ItemSizeSchema.optional(), // per unit; containers mode
  container: ContainerSchema.optional(), // present if the item holds other items
  wearable: z
    .object({
      slots: z.array(z.string().min(1)).min(1), // slots it can be worn in
      covers: z.array(z.string().min(1)), // other slots it hides while worn, e.g. a cloak over the belt
    })
    .optional(),
  bonuses: z.array(ItemBonusSchema),
});
export type Item = z.infer<typeof ItemSchema>;

export const EntitySchema = z.discriminatedUnion('kind', [
  CharacterSchema,
  PlaceSchema,
  FactionSchema,
  ItemSchema,
]);
export type Entity = z.infer<typeof EntitySchema>;
```

**Invariants**

- **CON-040** Every character has an `ageCategory`. The hard floor
  (`13-content-settings.md`) depends on it, so it never changes after creation
  (CSET-044).
- **CON-041** Every `EntityId` referenced by an entity (`locationId`, `parentPlaceId`,
  item locations) exists in the world state.
- **CON-042** An item location of `contained` references an item with a `container`;
  an item never contains itself, directly or indirectly; and every move satisfies the
  carrying rules (GEAR-053).
- **CON-043** A `worn` item's `slot` exists in the campaign's slot schema and is listed
  in the item's `wearable.slots`.
- **CON-044** `media` and `voiceProfile` are validated but ignored until phases 9 and
  10 (ARCH-132). Both are portable descriptions; machine-specific choices (voices,
  models) live in machine config and per-machine campaign state (MED-052).

## 7. World state — `world-state.ts`

```ts
import { z } from 'zod';
import { EntityIdSchema, GameTimeSchema, IdSchema } from './primitives';
import { EntitySchema } from './entities';
import { ClockSchema } from './rules';

export const FlagValueSchema = z.union([z.boolean(), z.number(), z.string().max(200)]);

/**
 * Current mutable facts at a turn on a branch. Produced only by applying commits
 * (`applyCommit` in core). Memory data (observations, grants, relationships, wiki)
 * lives in projections, not here.
 */
export const WorldStateSchema = z.object({
  gameTime: GameTimeSchema,
  sceneId: IdSchema,
  scenePlaceId: EntityIdSchema,
  pcId: EntityIdSchema,
  entities: z.record(EntityIdSchema, EntitySchema),
  clocks: z.record(z.string(), ClockSchema), // keyed by ClockId
  flags: z.record(z.string(), FlagValueSchema),
});
export type WorldState = z.infer<typeof WorldStateSchema>;
```

**Invariants**

- **CON-050** `pcId` references a character with `kind: 'pc'`, and exactly one such
  character exists.

### 10.1 Commit set rules

- **CON-080** Commits and commit sets are append-only. Once written, they are never
  edited or deleted (ARCH-040).
- **CON-081** A set is **active** unless a later set supersedes it. Regenerating or
  editing a stage of a turn creates a new set with `supersedesSetId` pointing to the
  set it replaces.
- **CON-082** Sets with stage `input`, `adjudication`, `resolution`, `narration`, or
  `extraction` are replaced by supersession. Sets with stage `setup`, `player-edit`,
  `world-tick`, or `consolidation` accumulate; they are superseded only by an explicit
  player edit of that set, or as `06-turn-engine.md` TRN-086 describes.
- **CON-083** A set lists the upstream sets it was generated from in `basedOnSetIds`.
  An active set is **stale** when any set in its `basedOnSetIds` is no longer active
  (e.g. a new ruling makes the resolution, narration, and extraction stale). Staleness
  is derived, never stored. Regeneration is defined in `06-turn-engine.md` §7.
- **CON-084** Application order within a turn is by stage in the order listed in
  `CommitStageSchema`, then by the set's `seq`, then by commit `seq`. Across turns,
  turn depth comes first (TRN-061). A set's `seq` is assigned by storage in creation
  order, campaign-wide, because ordering never relies on timestamps (CONV-054).
- **CON-085** Adding a commit type requires updating this document, the reducer or
  projection handler, and the allowlist table below, in the same change.

### 10.2 Commit allowlist

Semantic validation rejects any commit whose stage is not allowed for its type. The
ruleset may additionally permit `extraction` to emit commits for fields it marks
*narrative* (marked † below); it may also restrict them. `setup` sets (root turn only)
may contain any world-state or memory commit type (TRN-056).

| Commit type | Affects | Allowed stages |
|---|---|---|
| `input.set` | turn content | input, player-edit |
| `ruling.set` | turn content | adjudication, player-edit |
| `roll.record` | turn content | resolution |
| `resolution.record` | turn content | resolution |
| `narration.set` | turn content | narration, player-edit |
| `override.record` | audit only | any set with origin `player`, or any set with a non-null `supersedesSetId` (TRN-080) |
| `entity.create` | world state | resolution, extraction, world-tick, player-edit |
| `entity.update-narrative` | world state | extraction, world-tick, player-edit |
| `entity.move` | world state | resolution, extraction, world-tick, player-edit |
| `entity.death` | world state | resolution, world-tick, player-edit |
| `stat.change` | world state | resolution, world-tick, player-edit |
| `status.add` / `.update` / `.remove` | world state | resolution, world-tick, player-edit, extraction † |
| `harm.mitigate` | world state (armor uses) | resolution, player-edit |
| `clock.create` / `.tick` / `.delete` | world state | resolution, world-tick, player-edit, extraction † |
| `item.move` | world state | resolution, extraction, world-tick, player-edit |
| `item.quantity` | world state | resolution, extraction, world-tick, player-edit |
| `time.advance` | world state | resolution, player-edit (adjudication decides elapsed time, TRN-032) |
| `scene.start` | world state | resolution, extraction, player-edit |
| `tick.record` | world-tick log | world-tick (first commit of every world-tick set) |
| `flag.set` | world state | resolution, extraction, world-tick, player-edit |
| `observation.add` | memory | extraction, world-tick, consolidation, player-edit |
| `observation.amend` | memory | player-edit |
| `knowledge.grant` | memory | extraction, world-tick, consolidation, player-edit |
| `knowledge.revoke` | memory | player-edit |
| `knowledge.name` | memory | extraction, world-tick, player-edit (and setup) |
| `relationship.adjust` | memory | extraction, world-tick, player-edit |
| `relationship.set` | memory | player-edit |
| `wiki.patch` | memory | extraction, world-tick, consolidation, player-edit |
| `note.*`, `belief.*` | journal | player-edit |

- **CON-086** `entity.death` is rejected when the campaign's lethality setting forbids
  death for that character. Harm that would be fatal is converted according to
  `07-rules.md` instead.
- **CON-087** `relationship.adjust` deltas are limited to the ruleset's
  `relationships.maxChangePerTurn` (except in player edits), added, then clamped to
  `relationships.min…max` (RUL-141).
- **CON-088** Editing, regenerating, or retconning a turn that is in the ancestry of any
  *other* branch's head MUST NOT change that other branch. The engine copies the
  affected turns (copy-on-write) for the current branch and applies the edit to the
  copies; other branches keep the originals. Mechanism, including ID remapping for
  copied commits, is defined in `06-turn-engine.md`.

### 14.2 Routes

All paths are under `/api`.

| Route | Body | Response |
|---|---|---|
| `GET /session` | — | `SessionState` |
| `POST /session` | `PinLoginCommand` | `204` and a session cookie; `auth_failed` or `rate_limited` |
| `DELETE /session` | — | `204`; clears the cookie |
| `GET /packs` | — | `PackSummary[]`, packs with issues included (UI-083) |
| `GET /themes` | — | `Theme[]` from the built-in and user libraries and every pack |
| `GET /campaigns` | — | `CampaignSummary[]`, most recently played first |
| `POST /campaigns` | `CreateCampaignCommand` | `CampaignView`; the opening narration then streams as events |
| `GET /campaigns/:campaignId` | — | `CampaignView` |
| `DELETE /campaigns/:campaignId` | — | `204`; deletes the campaign folder |
| `GET /campaigns/:campaignId/events` | — | SSE stream of the campaign's `ServerEvent`s, honoring `Last-Event-ID` (ARCH-091, UI-101) |
| `GET /settings` | — | `MachineConfig`, secrets replaced (CON-111) |
| `PUT /settings` | `MachineConfig` | `SaveSettingsResult`; `validation_failed` lists every issue in `details` (PRV-002) |
| `PUT /settings/pin` | `SetPinCommand` | `204` |
| `GET /settings/providers` | — | `ProviderStatus[]` (PRV-091) |
| `GET /settings/providers/:providerId/models` | — | `string[]` |
| `POST /settings/profiles/:profileId/probe` | — | `ProbeResult` (PRV-090) |
| `GET /campaigns/:campaignId/turns/:turnId/model-calls` | — | `ModelCallSummary[]`, oldest first |
| `GET /campaigns/:campaignId/model-calls/:callId` | — | `ModelCallRecord` |

- **CON-110** A route that no spec document lists does not exist. A task that needs one
  adds it to the spec first (OVR-020).
- **CON-111** No response contains an inline secret or the PIN hash; each is replaced by
  `SECRET_PLACEHOLDER`. On `PUT /settings`, every placeholder is replaced by its stored
  value before validation: a provider's `apiKey.value` by the inline key stored for the
  provider with the same `id`, and `server.pin.hash` by the stored hash. A placeholder
  with no stored value is a validation issue at its path.
- **CON-112** `POST /campaigns` checks the whole command against the pack, the ruleset,
  and the creation rules (SCH-072, SCH-110 to SCH-116) and reports every issue at once,
  as SCH-100 does. On success the campaign folder exists, turn zero's `setup` sets are
  committed, and the opening narration is queued; the response does not wait for it.
- **CON-113** Only `GET /session`, `POST /session`, and the static client are exempt
  from the PIN (ARCH-110). The event stream needs a session like everything else.
- **CON-114** The event stream sends a comment line every 15 seconds while idle, so
  phone browsers and proxies keep the connection open.

## Traps

- **Reference contracts are linted only as copies (OVR-033).** Lint ignores `spec/`, so
  a change to `spec/reference/contracts/` is first linted in `packages/contracts/src/`,
  where the copy cannot be edited. A lint error there is fixed in the reference file and
  its code block in the documents, then copied again. Run
  `pnpm exec eslint --no-ignore spec/reference/contracts` before changing a contract.
- **`onmessage` never fires on the event stream (UI-101, UI-132).** Every frame names
  its event with the payload type (`event: narration.delta`), and `EventSource` fires
  `onmessage` only for frames with no `event:` line. A client adds a listener for each
  payload type, `resync.required` included:
  `source.addEventListener('narration.delta', …)`.

## Decisions

| Question | Decision | Rejected and why | Decided by |
|---|---|---|---|
| Where does a saved placeholder get its secret back from (CON-111)? | The provider with the same `id` in the stored config; the PIN hash from `server.pin.hash`. | The same array index: deleting or reordering providers in settings would shift the indexes and could give one provider another's API key, sending it to the wrong endpoint. | owner |
| What does the event stream send on the wire (§14.2, CON-114)? | Each event is one frame: `id: <id>`, `event: <payload type>`, and `data:` with the whole `ServerEvent` as JSON, then a blank line, every line ending in `\n`. Narration with line breaks stays on one `data` line, because JSON escapes them. The idle keep-alive is the comment `: keep-alive`, after 15 seconds with nothing sent. | `data` holding only the payload: the client parses each frame with `ServerEventSchema`, which needs the ID and campaign too. Splitting text with line breaks over several `data:` lines: JSON already keeps it on one, and the client would have to rejoin them. | Claude (ruling) |
| What does a `rate_limited` error carry (`POST /session`, ARCH-110)? | `details: { retryAfterSeconds }`, the whole seconds until the address may try again. The http module also sends the value as the `Retry-After` header. | The header alone: the client reads the error body and branches on its `code` (CON-090), so the wait belongs in the body too. | Claude (ruling) |
| What does `SessionState.authenticated` mean (§14.1)? | The request carries a live session cookie, whether or not this device needs a PIN. The client shows the PIN screen when `pinRequired` is true and `authenticated` is false. | "May use the API": for an exempt localhost or with no PIN set it would only repeat `pinRequired`, and say nothing about the session. | Claude (ruling) |
| What does `POST /session` return when no PIN is set (§14.2)? | `204` with no cookie: there is nothing to check, and every route already passes. | `auth_failed`: the client would show a wrong-PIN message for a lock that does not exist. A session anyway: it would grant nothing. | Claude (ruling) |
| Which relationships does CON-073 allow while the ruleset has no switch for factions? | Between characters only: `fromId` and `toId` must both be a pc or npc. | Allowing characters to factions now: CON-073 makes that the ruleset's choice, and no ruleset field records it yet. | owner |
| Where is CON-071 enforced? | When a set is written: `validateSet` in `core` rejects a set in which a witness of an observation it adds has no `witnessed` grant. The set builders, setup (SCH-117) and extraction (08-memory), add the grants. Replay does not check it. | Adding the grants inside the fold: the grants would exist only in folded state, not as commits, so row projections would not see them. | Claude (ruling) |
| What does a `null` mean in `relationship.set` and `flag.set`? | A `null` summary in `relationship.set` leaves the summary unchanged, and a new relationship's summary is `''`. A `null` value in `flag.set` removes the flag. | A `null` summary clearing the summary: `relationship.adjust` already uses `null` for "unchanged". | Claude (ruling) |
| What are an `illegal_state_change` error's `details`? | `{ issues: SemanticIssue[] }`, like `validation_failed` (CON-091), every issue at once. Each `path` is a dotted path into the set's entry, such as `commits.2.payload.to`. | A bare array: the client would read the two codes' details differently. | Claude (ruling) |
| Which sets may hold an `override.record` (TRN-080)? | Any set with origin `player`, and any set with a non-null `supersedesSetId`. A regenerated set keeps origin `model` (or `engine` for resolution, 06-turn-engine §7.1) and still records the player's instruction. | Only sets with origin `player`: a regeneration's `override.record` would be rejected. Giving a regenerated set origin `player`: the model wrote its content, and origin records who did. Keeping the instruction on the job: overrides would leave the commit log. | owner |

## Open
